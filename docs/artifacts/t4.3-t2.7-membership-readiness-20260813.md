## Can target-training participation be reconstructed exactly?

**From the current local T2.7 evidence: no.** The implementation is
deterministic enough to reconstruct participation if, and only if, the exact
observed event bytes, authenticated preparation metadata, and resolved training
configuration are restored:

1. `prepare_data` fits vocabularies and continuous statistics on every observed
   event with `timestamp <= train_end`; it records only aggregate rows and
   target-event counts, not per-user preprocessing participation.
2. `EventWindowDataset` stably groups the canonically ordered events by user.
   For each user it emits a target at every offset from
   `min_history_events` onward, retains up to `max_sequence_length` strictly
   earlier context events, and assigns the target to train, validation, or test
   solely by its timestamp.
3. `train_model` optimizes on every emitted train window. It evaluates every
   emitted validation window after every epoch and selects the checkpoint by
   minimum aggregate validation loss.

Consequently, exact user roles can be replayed from restored inputs by taking
the distinct `SampleReference.user_id` values in each dataset. They cannot be
recovered from the surviving index: it omits both event rows and the two window
configuration values, while its 49-user mask describes export coverage rather
than optimizer or validation participation. Aggregate `train_windows` and
`validation_windows`, even if the training reports were restored alone, would
still not identify the contributing users.

The contract is a **global temporal split, not a user-disjoint target-model
split**. A user may contribute training windows, validation checkpoint-selection
windows, preprocessing events, and later exports. “Validation” therefore does
not mean a held-out non-member population.

## Same-lineage member/non-member feasibility

**Primary encoder-training membership is unavailable for this lineage.** No
authenticated per-user membership labels can be assembled locally. Moreover,
the temporal-window contract does not reserve a user-held-out pool: it uses all
eligible users' train windows for optimization and all eligible validation
windows for checkpoint selection. Any users who happened to lack train windows
would be incidental late/sparse-history cases, not automatically clean
non-members; preprocessing or validation participation must first be excluded.

There is therefore no demonstrated same-lineage member/non-member population,
and common support cannot be assessed. The index's 49-user common export mask
shows representation availability only. The seven “held-out probe users” in
the factorization decision are evaluator probe coverage, not authenticated
target-training non-members. Neither group may be relabeled. Users from the
T3.5, smoke, another seed, a regenerated source hash, or another scenario are
prohibited substitutes.

A future readiness check must construct roles before attack outcomes, then test
overlap on public history-count, first/last-observation, cutoff-availability,
and service/observation-coverage strata. Until both classes have adequate
support in those strata, membership AUC remains unavailable rather than being
computed on a redefined population.

## Required next action

For historical reproducibility, restore the exact indexed T2.7 experiment
bytes **and** the source run bytes matching the recorded SHA-256 values. That
would permit an exact retrospective participation replay, but it cannot create
a clean non-member cohort if the replay confirms that none was reserved.

For an executable diagnostic-control membership audit, generate a **new,
immutable matched diagnostic lineage** whose preparation/training contract
predeclares a user-level target-training cohort and a same-source held-out user
cohort. Freeze per-user optimizer, validation/checkpoint-selection, and
preprocessing participation records; encode held-out users only after the
checkpoint is frozen; preserve identical cutoffs and representation
availability; and index all source, preparation, checkpoint, export, utility,
and participation artifacts. All six diagnostic representations must share
that one lineage and split. This new lineage must receive a new identity and
must not be presented as restored T2.7 evidence.

Thus restoration is necessary only to audit the historical T2.7 model exactly;
**a new matched diagnostic lineage is necessary for a usable primary
member/non-member experiment unless restored records unexpectedly demonstrate
an adequate, uncontaminated held-out population.** Current evidence does not
demonstrate such a population, so primary membership stays unavailable.
