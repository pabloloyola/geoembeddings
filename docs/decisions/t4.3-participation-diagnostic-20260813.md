# T4.3 fixed-seed training-membership diagnostic lineage

## Scope and identity

This is a new immutable R12 diagnostic lineage, not a continuation of T2.7 and
not a replacement for a selected-candidate privacy audit. It uses simulator seed
`20260813`, 100 same-lineage users, the statistical baseline, and all six learned
T2.7 diagnostic controls. The authoritative machine-readable index is
[`docs/artifacts/t4.3-participation-diagnostic-20260813.json`](../artifacts/t4.3-participation-diagnostic-20260813.json).
Every run, experiment, participation record, export, checkpoint, preparation
record, command, seed, and available hash is indexed there. Utility reports are
explicitly indexed as not generated because the membership gate failed before
an attack or utility/privacy comparison; no utility or selection claim is made.

## Participation and preprocessing result

All six learned controls share the same participation identity:

- 90 users contributed 1,290 eligible training windows;
- 89 users contributed 407 validation/checkpoint-selection windows;
- 10 same-lineage users contributed neither training nor validation targets;
- 3 of those 10 were nevertheless seen by train-fitted preprocessing and have
  frozen exports, so they are not clean pipeline non-members;
- 7 were clean pipeline nonparticipants, but none has an observed history or a
  frozen export.

The statistical baseline has no learned target parameters, so training
membership is `not_applicable`. Its preparation-reference counts are recorded
only to expose the shared pipeline population; they are not baseline membership
labels.

## Frozen strata and attack gate

The public-history, cutoff-availability, and service-coverage bins are applied
exactly as frozen in `configs/privacy/diagnostic_v1.yaml`; the realized stratum
counts are serialized in the index. The 90 members all occupy three-cutoff
export strata. The seven clean nonparticipants occupy the zero-history,
zero-cutoff, zero-service stratum. Consequently there is no common support and
no clean nonmember with an attack vector.

The membership result is therefore explicitly **unavailable**. Eligible = 100,
matched = 0, unmatched = 100, excluded = 100, and realized member/non-member =
0/0. No attack was run: minimum total 100, minimum per class 20, and minimum per
stratum 10 all fail on the realized matched population. This is unavailable
evidence, not evidence of privacy.

## Temporal-contract decision and next scope

The current global temporal split cannot support training membership without a
model-training change. Every exportable user is exposed to train-fitted
preprocessing, while the only clean pipeline nonparticipants have no history to
encode. A separately scoped held-out-user lineage must reserve users before
preprocessing and target-model training, then export those users using a frozen
pipeline. That task is required next and is not silently implemented or claimed
complete here.
